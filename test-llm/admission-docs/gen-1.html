List shipments

GET https://api.northwind.com/v2/shipments

Retiring 1 March 2027

This endpoint is being retired

GET /v2/shipments stops responding on 1 March 2027. After that date every call returns 410 Gone. Move your integration to GET /v3/shipments before then.

v3 keeps the same filters but returns cursor pagination by default and renames status values to the carrier-neutral set. Nothing else in your request has to change.

Read the v3 reference Migration guide

Returns a paginated list of shipments belonging to the authenticated account, newest first. Use the query parameters below to narrow the list by lifecycle status, origin hub, or last update time. A shipment appears here from the moment a label is purchased until 24 months after delivery.

Requires an API key with the shipments:read scope.

Query parameters

Name Type Required Description
status string Optional Filter by lifecycle state. One of draft, in_transit, delivered, exception, cancelled. Repeat the parameter to pass more than one value.
origin_hub string Required Three-letter hub code the shipment departs from, such as RTM or MEM. Accounts with a single hub may omit this only on v3.
updated_after string (RFC 3339) Optional Only return shipments changed at or after this timestamp. Use it to poll for changes instead of re-reading the whole list.
limit integer Optional Number of shipments per page, between 1 and 200. Defaults to 50.
cursor string Optional Opaque cursor taken from next_cursor in a previous response. Omit it to start at the first page.
include string Optional Expand related records. Accepts packages, events, or both as a comma-separated list.

Common questions

Will my v2 calls break before 1 March 2027?

No. v2 keeps working normally until that date, and we will not change its response shape in the meantime. From 1 March 2027 the endpoint returns 410 Gone with an error body pointing at /v3/shipments. From 1 December 2026 responses also carry a Sunset header so you can alert on it from your own logs.

Why do I get 400 when I omit origin_hub?

On v2, origin_hub is required for every account, including single-hub accounts. Pass the hub code shown on your dashboard. On v3 the parameter is optional and defaults to all hubs the key can read.

How do I page through more than 200 shipments?

Read next_cursor from the response and pass it back as cursor on the next call. Stop when has_more is false. Do not build cursors yourself; their format is not stable between versions.

Is there a way to be told about changes instead of polling?

Yes. Subscribe to the shipment.updated event described in Shipment webhooks. Polling with updated_after is the fallback when you cannot receive inbound requests.
